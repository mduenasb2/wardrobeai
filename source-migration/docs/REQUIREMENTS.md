## Non-functional requirements

| ID | Requirement | Rationale / origin | PC design note |
|---|---|---|---|
| NFR-001 | PC app must run locally without Android APIs or mandatory third-party dependencies. | Prompt constraint; not original app behavior. | Python standard library server plus native browser HTML/CSS/JS. |
| NFR-002 | No selected image needs to persist between sessions. | Derived from ViewModel-only state and absence of storage calls for inputs; `src_ev_wardrobeai_viewmodel_state_001`. | Images stay in browser memory; only user-requested PNG download reaches disk. |
| NFR-003 | Do not ship an API secret in the PC source or browser bundle. | Engineering requirement introduced for this reconstruction; original app reads `local.properties` into `BuildConfig` (`src_ev_wardrobeai_build_configuration_001`). | Optional Gemini credential is an environment variable read by loopback server; missing secret activates local fallback. |
| NFR-004 | Clearly communicate that local compositing is a simple overlay, not learned garment fitting. | Engineering transparency decision motivated by observed fixed geometry (`ev_6563e4ebbe1d21ccf2c19af9a2988fda875f93f3adb0a0a270af097e43d57b51`, `src_ev_wardrobeai_fallback_composite_001`). | Local-only status text identifies the output as a preview; full body segmentation is not claimed. |
| NFR-005 | Validate file data and bound the local request size. | PC engineering-quality choice; not a discovered Android business rule. | Server verifies image MIME/data URL/base64 and enforces an 8 MiB decoded-image and 24 MiB request limit. |
